# Plan: Improve Graph Relationships in StoneLink Import Script

## Objective
Propose targeted improvements, changes, or additions to the relationships in the `import_data.py` script's graph model to better reflect quarry operations, enhance queryability, reduce hard-coding, and prepare for scalability. Ensure proposals are data-driven, aligned with CSV contents, and maintain logical consistency.

## Current Analysis
- **Strengths**: Relationships model core flow (extraction → transport → processing), with supporting elements (operators, events). Data-aligned, no orphans.
- **Weaknesses**: Hard-coded assignments limit flexibility; missing properties (e.g., quantities, timestamps); potential gaps (e.g., multi-assignment, indirect links).
- **Tools Needed**: Read code/data for context; search for graph modeling best practices in supply chain/logistics domains.

## Proposed Improvements
1. **Add Properties to Existing Relationships**:
   - Add `cantidad_ton` (quantity in tons) to `TRANSPORTA` and `GENERA` (using `capacidad_ton` from CSVs as max).
   - Add `fecha_inicio` (start date) to `OPERA_EN`, `TRABAJA_EN`, `USA` for temporal modeling.
   - Add `duracion_horas` (duration) to `AFECTA` for event impact analysis.

2. **New Relationships**:
   - `Operador SUPERVISA Planta`: If operators manage processing (link via `TRABAJA_EN` extensions).
   - `Evento AFECTA Mina`: For extraction disruptions (e.g., weather events).
   - `Camion CARGA_EN Mina`: To explicitly model loading (currently implicit via `OPERA_EN`).
   - `Planta RECIBE_DE Camion`: Reverse of `TRANSPORTA` for inbound tracking.

3. **Modify Existing Relationships**:
   - Change `TRANSPORTA` to allow multi-material/multi-plant (remove hard-coding; use queries for assignments).
   - Add conditional logic in `create_relationships()` to assign based on data (e.g., match via capacities or locations).

4. **Remove/Consolidate**:
   - None major; consider consolidating `OPERA_EN` and `CARGA_EN` if redundant.

5. **General Enhancements**:
   - Use parameterized queries for relationships (avoid hard-coding IDs).
   - Add validation: Check for missing links (e.g., all materials have sources/processors).
   - Prepare for dynamic data: Support CSV updates without script changes.

## Steps to Implement
1. Review code and CSVs for constraints (e.g., capacities must match assignments).
2. Research Neo4j best practices for quarry/logistics graphs.
3. Draft updated `create_relationships()` with proposals.
4. Test with sample data for consistency.
5. Validate against user requirements (e.g., scalability needs).
